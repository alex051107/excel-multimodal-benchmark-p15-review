# Judge V3 Contract

## 题面明确必须结果

- 账单头信息、每笔交易的借/贷方向、续页页码和可读溯源信息正确。
- 从期初余额到打印期末余额的对账正确。
- 包含简洁类别汇总；类别措辞可变，只要业务含义一致。

## 保留的动态要求

题面明确要求 formula-linked reconciliation，并要求修改交易金额时对账响应。期初、贷方合计、借方合计和计算期末必须由公式连接；与打印期末的比较也必须保持正确。

## V3 删除的非必要惩罚

- 删除交易、类别表和对账表必须位于固定行/格的要求，改为通过可见标签和表头定位。
- 不再要求固定工作表名；工作表的业务角色也由可见标签和表头确定。
- 交易的 net-impact 列和类别汇总可使用公式或正确静态值；它们不是题面明示的动态链。
- 不强制一笔交易对应一个固定类别名，允许语义清晰的合并类别。

## 新正反例

- 正例 `shifted_dynamic_layout`：所有表格移动两行后对账链仍完整响应，应得 1.0/通过。
- 正例 `renamed_sheets`：全部工作表改名但可见业务表头完整，应得 1.0/通过。
- 反例 `wrong_opening_link`：对账引用错误期初金额，必须在 R006/R007 失败。

实际分数与通过状态见 `receipts/judge_v3_local_validation.json`。
