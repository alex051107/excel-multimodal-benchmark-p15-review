# Judge V3 Contract

## 题面明确必须结果

- 报价头信息和每个 scope 行正确，行 ID 与可读溯源信息一致。
- 基础范围与可选项明确分开。
- 基础范围小计、折扣、税和最终总额正确，且最终总额不包含可选项。

## 保留的动态要求

题面没有要求特定单元格必须使用公式，也没有要求扰动响应。V3 只保留业务不变式：基础范围、折扣、税和最终总额必须算术一致，可选项不得进入基础总额。

## V3 删除的非必要惩罚

- 删除对特定公式、固定行/格位和扰动链的要求。
- 不再要求固定工作表名；使用可见表头和标签识别业务角色。
- 不要求折扣必须以正数或负数中的某一种方式表示。
- 不因为未使用 oracle 的组名措辞而判错；只检查基础范围和可选项的真实业务归属。

## 新正反例

- 正例 `static_shifted_layout`：正确静态总额、负数折扣表示且表格移行，应得 1.0/通过。
- 正例 `renamed_sheets`：全部工作表改名但可见业务表头完整，应得 1.0/通过。
- 反例 `wrong_total`：基础范围最终总额错误，必须在 R006/R007 失败。

实际分数与通过状态见 `receipts/judge_v3_local_validation.json`。
