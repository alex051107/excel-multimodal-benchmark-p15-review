# P15 Judge V3 判分合同

## 这份合同先于本轮改分

本轮可以修改评分程序，但不能根据某个系统原来得分高低决定规则。每道题先以用户题面、输入材料和真实交付目的确定必须完成的事情，再允许多种 Excel 实现。评分程序改完并冻结后，才统一重算归档中的 364 份工作簿。

当前 Judge V2 自带的 125 个测试样例全部通过。这只能证明程序符合自己原来的测试，不能证明扣分合理。真实工作簿已经暴露出固定表名、固定起始行、固定单元格、特定文字和未在题面说明的公式要求。V3 用下面的合同决定哪些检查保留。

## 共用判分规则

1. 题面明确要求的业务结果可以计分；会改变使用者决定的错误可以扣分。
2. 只有题面明确要求“公式联动”“修改输入后自动更新”或原生 Excel 对象时，才把动态行为列为通过条件。
3. 表名、列顺序、起始行、单元格地址、正负号表示法、文字同义表达和中间表数量默认可以变化。评分程序应按表头、标签、ID 和数值关系查找。
4. 同一事实存在多种等价公式时，检查结果和输入变化后的响应，不要求公式文本与参考答案相同。
5. 缺少业务结果可以扣分；评分程序找不到合理布局时返回 Judge 错误，不能写成 0 分。
6. 任务来源、单位或参考答案有错时，先把题目标为无效。不能通过修改 Judge 让错误参考答案继续得到 1 分。
7. 每个关键规则至少要有一个正确等价样例和一个真实错误样例。样例按交付特征设计，不按模型名称设计。

## 改完以后怎样重算

1. 每题先运行标准答案、等价答案、空白文件、损坏文件和故障样例。
2. 再运行新增的替代布局、等价公式和同义标签样例。
3. 15 个 Judge 的代码和评分要求固定后，记录各自哈希。
4. 使用 `current_campaign_workbook_manifest.csv` 中全部 364 条 `INCLUDED` 工作簿统一重算。134 条没有工作簿的回执继续单列，不给 0 分。
5. 原生透视表需要 Excel 回读的结果单列为“待原生重算”；任务无效、Judge 无法判断和数值未通过分别统计。
6. 新分数只表示这份合同下的完成程度。是否能比较三个系统，还要看每题是否有足够且对称的可评分样本。

## 政策题的历史批次与修正版

历史答卷收到的任务把数据称为 EIA 来源，但来源定位实际指向英国 BEaC；参考计算又把 GWh 直接乘以 tCO2/MWh，少了 GWh 到 MWh 的 1,000 倍换算，基准天然气和“其他发电”的关系也没有说清。这个问题来自任务合同，不是答卷本身。因此，历史批次的 24 份政策题工作簿全部记为“任务无效”，不计算 V3 分数。

修正版把现有数值明确写成“以 EIA 公共发电表为背景、由项目取整和改写的情景输入”，不再称为某张表的逐项摘录；4,000,000 GWh 的需求量明确为项目设定。修正版还固定了 `GWh × 1,000 × tCO2/MWh` 的排放计算，以及“基准天然气保持历史值、其他发电保持不变、政策情景由天然气补齐需求”的关系。它只用于验证未来 Judge 和以后重新发题，不能反过来给历史答卷扣分。
